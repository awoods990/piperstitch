Where recruitment sends from — {% if mailbox.host %}{{ mailbox.host }}{% else %}Postmark (not moved yet){% endif %}

Postmark’s terms allow only mail people asked for, and one spam complaint in a hundred cold sends is ten times their stated limit — against the account that also carries sign-in codes and proof links. Sending recruitment out of a mailbox you own keeps the two apart.

Google Workspace: smtp.gmail.com, port 587, an App Password (the account needs 2-Step Verification for one to exist). Microsoft 365: smtp.office365.com, port 587, the mailbox password, with SMTP AUTH enabled for that mailbox — Microsoft turns that off by default at the end of December 2026.

{% endif %}

What it costs. A mailbox hands back no message id, so opens and clicks stop being recorded for anything sent this way. Replies keep reaching this page only while “replies go to” points at Postmark’s inbound address; point it at a real inbox and you read them there instead. Send 10–20 a day from one mailbox — more looks like bulk to Google and Microsoft both.

Open and click tracking — one URL to paste into Postmark

Postmark reports an open or a click back to us here. Until this URL is in place, the columns below count only people who reached the details page — which is a click-through, not an open, and a much smaller number.

Postmark → your server → Webhooks → Add webhook. Paste this, and tick Open and Link Click:

Tracking has to be switched on for the server as well (Postmark → Settings → Tracking). The URL is its own password, so treat it like one — and it changes if SESSION_SECRET is ever rotated, in which case paste the new one here.

Read opens as directional, not true. They work by a hidden pixel: Apple Mail Privacy Protection loads it whether or not anyone looked, and clients that block images never load it at all. Clicks are the honest number.
